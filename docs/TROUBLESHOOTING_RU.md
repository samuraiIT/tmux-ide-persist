# Найденные на сервере проблемы и решения

Ниже обобщён опыт Remote SSH + Antigravity/xterm.js + tmux. Исторические
обходы зависят от версии IDE/CLI; они не включаются массово в конфиги друга.

| Симптом | Причина и действие |
|---|---|
| После reconnect пустой bash вместо живого CLI | Процесс может жить в detached-сессии. Выполнить `ide-tmux list`, затем `ide-tmux attach ИМЯ`. Смена IDE nonce или размера окна не должна определять идентичность задачи. |
| Несколько вкладок повторяют одно окно | Они подключены к одному имени. Использовать отдельные явные имена сессий. На исходном сервере также встречались grouped-сессии с общим набором окон. |
| После закрытия IDE процесс исчез | Он был запущен до входа в tmux, выполнен `exit`, перезагружен сервер или user-session cleanup остановил процессы. Проверить `echo "$TMUX"`, список сессий и политику logind. Не менять logind глобально без диагностики. |
| Правый клик открывает Horizontal Split / Vertical Split | Это tmux pane menu. Конфиг комплекта проглатывает MouseDown3Pane и Alt+правый клик. В IDE использовать клиентское меню Copy/Paste; Ctrl+Shift+V — запасной способ вставки. |
| Нет скролла или выделения в CLI | Отделить mouse tracking самого CLI от tmux. Оставить `mouse on`; историю tmux открыть Ctrl+b `[`. В некоторых терминалах Shift+выделение обходит mouse tracking; проверить вручную. |
| После перезапуска IDE вставляется старый текст | Столкнулись IDE process revive и tmux recovery. На исходном сервере помог `persistentSessionReviveProcess: never`; сохранение процесса обеспечивает tmux. |
| В prompt видны `11;rgb:...` / OSC-ответы | Исторический конфликт разбора escape-sequences. `escape-time 100` помогал на исходном сервере. Не добавлять очистку stdin или RIS reset вслепую: можно потерять настоящий ввод. |
| Большой текст вставляется кусками | Проверить bracketed paste и путь IDE → PTY → tmux → приложение. Для bash проверить `bind -v` и `set enable-bracketed-paste on` в пользовательском inputrc. Не отключать защитные предупреждения IDE автоматически. |
| Скриншот drag&drop не доходит | Виртуальные файлы clipboard/скриншотилки могут теряться на клиенте Electron ещё до SSH. Сначала сохранить изображение обычным файлом и передать через SSH/SFTP. Это не дефект сохранения tmux-сессии. |
| После изменения конфига поведение старое | tmux server живёт дольше IDE. После review применить только конфиг комплекта: `tmux -L ide-persist source-file /path/to/tmux-ide-persist/config/tmux.conf`. Клиентские настройки IDE требуют Reload Window. |

В исторических документах исходного сервера встречались разные профили
правого клика (`paste` и позднее `default`) и Claude TUI (`fullscreen` и
`default`). Переносимый комплект выбирает клиентское меню `default` и не меняет
конфигурацию Claude/Codex. Настройку конкретной версии проверяйте вручную.

Не используйте `tmux kill-window -a`, `kill-session` или `kill-server` как
«восстановление». Они могут завершить нужные процессы. Сначала список сессий,
потом attach к явному имени. Логи `tmux -v/-vv` и capture-pane могут содержать
секреты: не публикуйте их без проверки.

Если пакетный tmux не знает `tmux-256color`, установите соответствующий terminfo
пакет ОС либо после проверки совместимости используйте `screen-256color`.
Если shell не запускается, проверьте корректность `$SHELL` и доступность login
shell; комплект не переносит пользовательские shell hooks исходного сервера.
